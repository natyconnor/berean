Passage Memory

An explicit mode on eligible scope packs: learn a contiguous passage as a scaffolded rope — multi-day fading hints per piece, short mixed support recitations, pass at 85%, and ordinary hearts stay independent.

Settled decisions

Decisions locked before implementation

Fixed constraints from the product owner plus defaults locked so implementers do not fork the model. Treat as non-negotiable.

Decision Resolution
Mode on a scope pack, not a new object Passage learning is an opt-in mode on an eligible scope pack — not a separate top-level concept, and not automatic on create. Default scope packs remain heart collections. Schema packs.kind stays "scope" | "custom". The passage row is 1:1 with the pack while the mode is active.
Opt-in and undo Eligible pack view primary CTA: “Learn as a passage” → passageMemory.start. Optional builder shortcut: “Create and start passage learning” still creates a normal scope pack, then lands with intent to start (same mutation; not silent). While status === "building", offer “Stop passage learning” → passageMemory.stop removes the passage row and returns the pack to a plain heart collection (hearts untouched). After reviewing/mastered, stop requires confirm; same cleanup. Never auto-start merely because the pack was opened.
Progressive part, not a verse queue A passage has a frozen piece list, a scaffolded rope, and a frontier. Pieces are not hearts and are not independent SRS cards in the global verse queue. Do not auto-heart a chapter in order to learn it.
Piece size Reuse groupChapterForHearting with empty existing hearts so user hearts never fragment the piece list. Same caps: MAX_GROUP_VERSES = 4, MAX_GROUP_WORDS = 60, sentence / heading / paragraph splits.
Independent hearts Hearting a verse inside a passage scope still creates a normal savedVerses + verseMemory card. Users can Learn / Review / Practice that heart on its own. Unhearting it does not change passage pieces. Passage progress never writes those rows (except the one-time migration unheart below). Duplicate due items are OK.
Scaffolded rope (not same-day encode) Keep the full verse-style fade ladder on each piece: Read → Guided → Challenge → From Memory, with the same overnight soft-lock after clearing Guided or Challenge (reuse isLearningSessionEndingStage / dueAtInCalendarDays). Do not compress to a one-session Read→Memory→join. Soft-lock is per piece (the piece that just ended a session band); rope rehearsal of other attached/solid pieces remains available the same day.
Attach ≠ solid Per piece attachment: unreached → learning (introduced, Read/Guided) → attached (on the rope) → solid. Attach only after the piece clears Guided (Read alone does not attach — it is not yet learning). While attached, the piece still walks Challenge → From Memory over later days. Solid when From Memory clears (graduate that piece). Connecting practice uses attached + solid pieces; learning-only pieces are drilled alone until attach.
Mixed-support rope recitation Prefix / section / passage practice is one typed attempt over the rehearsal window, but the prompt is a composite mask: each piece’s hint density comes from its own learnStage via hintForProgress (solid → blank; attached Challenge → cloze; attached Guided should not happen — Guided clears before attach; learning pieces are not in the rope). Grade with word diff + 85% pass; stall-map to the weak piece. This is how different memory levels meet in a single test.
Daily introduce budget PASSAGE_MAX_ADDS_PER_DAY = 5 counts pieces introduced (first entering Read / leaving unreached), not attaches or solids. Encourage at least one introduction per local day while building. After an introduction session ends (or the frontier soft-locks), offer “Introduce another piece” vs “Done for now” when budget remains and the next piece is unreached.
Pass threshold Passage attempts pass at accuracy >= LEARN_PROGRESS_ACCURACY (85), same bar as verse Guided banking. Applies to frontier band reps, rope recitation, stall-repair clear, section-complete, and finished-passage review scheduling. Do not require exact to move on. Below 85% is a retry / stall, not a day-long add lock.
Sections + rehearsal window Large sections start at a new chapter or an ESV heading/subheading. Default rope warm-up does not always start at verse 1: rehearsal start is max(sectionStart, ropeEnd - PASSAGE_REHEARSAL_MAX_PIECES) with PASSAGE_REHEARSAL_MAX_PIECES = 3, then trimmed so the window’s word count stays ≤ PASSAGE_REHEARSAL_MAX_WORDS = 120 (drop oldest first). Window includes only attached + solid pieces. Explicit actions: “From the start of this section” and “From the beginning of the passage” (no word cap). After the last piece of a section becomes solid, offer optional full-section recitation. When every piece is solid, status → reviewing; Review is the whole passage (blank).
Stalls A failed rope recitation (<85%) is a stall, not skip-to-next-card. Map the first non-typo error to a piece, cue with the end of the previous piece plus first letters of the stalled piece, retry from one piece earlier. After repair ≥85%, continue (back to rope practice or frontier drill). Rough warm-up must not block introducing a new piece for the rest of the day — repair, then continue.
Speaking mode Out of scope. Typed recall (existing textarea + word diff) remains the only input. Do not add mic / speech APIs.
Who can start passage mode Eligible: kind === "scope", contiguous chapters in one book (scopeChaptersAreContiguous), chapter count 1–20 (AUTO_HEART_MAX_CHAPTERS). Custom packs, tagged whole-corpus scopes, multi-book scopes, and over-cap ranges stay heart collections only (no CTA).
Migration of auto-hearted packs Runs inside passageMemory.start when the user opts in (also if they start from a global unified pack card via an ensure/start path) — not on every pack open. Idempotent: existing row → return it. Else compute canonical pieces (empty hearts). Infer per-piece attachment / stages from covering hearts (review/mastered → solid; learning-phase coverage → map stage; else unreached). If looksLikeAutoHeartedPassage, unheart matching spans via existing unheart path (keep verseMemory history). Keep non-matching user-shaped hearts. Clear unifiedReviewEnabled. One-time banner with unheart/keep counts. Never regroup pieces after start.
Unified recitation Keep setUnifiedReview / recordUnifiedReview for packs that never start passage mode. Once a passage row exists, review through passageMemory only. Do not delete unified code in this plan.
Global queues Building passages appear in Learning as one card when any piece is due for learning (frontier due) or rope practice is available — not as N verse cards. Reviewing passages appear in Review as one card. Remaining hearts in the scope stay visible as individual due verses.

Shared architecture

Data model & core contracts (referenced by every PR)

Mental model

A heart is still a user-chosen verse (or short span) in savedVerses with its own verseMemory ladder. A scope pack is a named collection (hearts in range). Passage mode is an opt-in overlay on an eligible scope pack: the user is memorizing that range as one growing, scaffolded recitation. Pieces are derived groupings stored on the passage row, never as hearts. Each piece has an attachment: unreached → learning (Read/Guided) → attached (on the rope after Guided clears; still Challenge / From Memory) → solid (From Memory cleared). The rope = attached + solid pieces. The frontier = lowest index that is not solid (learning or attached). Unreached pieces show on the map but are not in any queue until introduced.

Due-queue integration

Extend dueQueuePackItem (keep kind: "pack") with optional passageStatus and members sourced from passageMemory.pieces when a row exists. Building passages are not review-due; they increment memoryStats.learningDue by 1 when a learning session is available today (any non-solid piece with dueAt missing or ≤ now, or an unreached piece with remaining introduces — see Architecture comment in code). Soft-locked frontier with no introduces left still allows rope practice from the pack but should not inflate learningDue. Reviewing/mastered passages use isDueForReview on the passage row and count as 1 in due.

After start, that pack must not contribute members to unifiedReviewPhaseVerseRefIds (flag is cleared). Leftover hearts stay in the verse due scan.

Global Learning: add building passage cards the same way Review merges pack cards — prefer a small passageMemory.dueForLearning (or extend verseMemory.learningQueue) rather than stuffing into listAll.

Unheart helper

Extract the remove-branch of savedVerses.toggle into unheartByVerseRefId(ctx, userId, verseRefId, now) in convex/lib/savedVerses.ts (or convex/lib/verseMemory.ts next to deletePackMembershipsForVerse). Both toggle and start call it. Stats, isHearted, membership cleanup, and “keep review history” stay identical.

Data flow

User creates a scope pack (collection by default). On an eligible pack they click Learn as a passage (or builder shortcut). Client fetches chapters, buildPassagePieces, calls passageMemory.start. Session runs reducePassageSession: optional rope warm-up with per-piece composite hints, frontier drill with full fade ladder and per-piece soft-lock, introduce next unreached when budget allows. Clearing Guided attaches the piece to the rope; clearing From Memory makes it solid. When all solid, Review is one blank composite; recordAttempt({ kind: "review" }) schedules the passage row (≥85%). Stop removes the passage row. Old auto-hearted packs only migrate when the user starts passage mode.

Conventions every PR must follow

Workflow

  • One PR at a time, in order. Read files before editing.
  • After code changes run pnpm run agent:check (format → lint → typecheck).
  • Run pnpm test for any PR that adds/edits a *.test.ts or *.test.tsx.
  • Regenerate Convex types with pnpm run codegen after schema/function changes.
  • Never commit or push unless the orchestrator asks. Leave the working tree dirty for the checkpoint commit.
  • Update CHANGELOG.md only in PR 8 (one feature entry). Do not bump the package version.

Convex and product rules

  • Every public query/mutation has args and returns validators.
  • Auth via getCurrentUserId / getCurrentUserIdOrNull; verify pack ownership with loadOwnedPack.
  • Never call Date.now() inside a query — pass now in. Mutations may use Date.now() for createdAt.
  • Query with .withIndex(...), never .filter(...) for user-scoped scans. await every promise.
  • No any; use generated Doc<> / Id<> types.
  • Do not create hearts when starting passage mode. Do not hide leftover hearts from the due queue after start. Do not auto-start passage mode on pack open.
  • Do not add speech/mic UI. Do not regroup frozen pieces. Keep the full Read→Guided→Challenge→From Memory ladder with per-piece soft-locks — no same-day compressed encode.
  • Custom packs and ineligible scopes must keep today’s heart-member behavior. Eligible packs stay collections until the user starts passage mode.
