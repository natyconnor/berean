Desktop Electron + iPad PWA

Ship a Mac Electron thin shell that loads production web, signs in through the user's browser and keeps itself up to date, plus an installable iPad PWA — same React app, same Convex backend.

9 pull requests Electron + electron-builder (Mac) no Capacitor in this plan revised 2026-11-15
How to use this document. Each numbered block below is one pull request. Do them in order. Do not start the next PR until the current one is green: implement only what that PR lists, run pnpm run agent:check, satisfy the PR's acceptance criteria, then stop. The run-implementation-plan skill orchestrates this. PRs 1–7 are the Mac release. PRs 8–9 add sign-in options and are proposed, not yet confirmed — do not build them until the product owner says which ones they want.
What changed in the 2026-11-15 revision. Nothing in this plan had been built when it was revised.
  • Sign-in now happens in the user's default browser and returns to the app through berean://auth. The old in-window Google sign-in is gone (Google's policy disallows sign-in from embedded browsers). No Convex changes are needed.
  • The shell updates itself with electron-updater. Users download the app from the website once and never again.
  • Desktop has its own version and its own release location (natyconnor/berean-desktop), separate from the web app's release-please releases.
  • Universal Links are dropped. No AASA file, no App ID, no Associated Domains. berean:// links still open the app.
  • Two proposed PRs added: email sign-in code (PR 8) and Sign in with Apple (PR 9).
Human only

Manual steps you must do (agents cannot)

Read this first. Agents implement code and CI wiring. Apple setup, the releases repo and secret injection require you. Do items 1–4 before or during the build; item 5 once PR 6 is merged. Items 6–7 are only needed if you go ahead with PRs 8–9.
  1. Developer ID Application certificate — In your Apple Developer account, create a Developer ID Application certificate (only the Account Holder can). Install it in Keychain, then export it as a .p12 with a password. As of 2026-11-15 this Mac had no signing certificates installed. You do not need to register an App ID for this plan.
  2. Notarization key — In App Store Connect → Users and Access → Integrations, create a Team API key (Developer role is enough). Save the .p8 file (it downloads once), the Key ID and the Issuer ID.
  3. Releases repo — Create a public GitHub repo natyconnor/berean-desktop with just a README. It holds desktop downloads and the update feed, nothing else. Then create a fine-grained personal access token limited to that repo with Contents: read and write.
  4. GitHub Actions secrets on natyconnor/berean:
    • CSC_LINK — base64 of the Developer ID .p12
    • CSC_KEY_PASSWORD — password for that p12
    • APPLE_API_KEY — contents of the .p8
    • APPLE_API_KEY_ID
    • APPLE_API_ISSUER
    • DESKTOP_RELEASES_TOKEN — the token from item 3
    Until these exist the workflow builds an unsigned .dmg as a workflow artifact only. An unsigned build cannot auto-update and is not published.
  5. Smoke-test on a Mac — Run the release workflow, then: install the .dmg; sign in with Google (your browser opens, then hands back to Berean); quit and relaunch (still signed in); open a second window; turn off the network to see the offline screen; run open berean://passage/John-1. To test updating, bump the desktop version, run the workflow again and confirm the installed app offers to restart into the new version.
  6. Only for PR 8 (email code) — Create a Resend account, verify a sending domain (DNS records on nathanconnor.dev), create an API key and set it as AUTH_RESEND_KEY in Convex for dev and production.
  7. Only for PR 9 (Sign in with Apple) — In the Apple Developer account create an App ID with the Sign in with Apple capability, a Services ID, and a Sign in with Apple key. Set the return URL to <CONVEX_SITE_URL>/api/auth/callback/apple. Generate the client secret and set AUTH_APPLE_ID and AUTH_APPLE_SECRET in Convex. Apple client secrets expire after at most six months, so set a reminder to regenerate.

Nothing to change in Google Cloud: the OAuth redirect URI stays the Convex callback it is today. Convex production SITE_URL is already https://berean.nathanconnor.dev (checked 2026-11-15), which the browser sign-in return relies on.

Out of scope for you this round: Windows signing cert, Linux packages, Capacitor / App Store, offline Bible, touch/pen iPad redesign, full marketing homepage.

Settled decisions

Decisions locked before implementation

Decision Resolution
Desktop shell Electron thin shell loads https://berean.nathanconnor.dev (override via BEREAN_DESKTOP_URL for local/dev). Does not bundle the Vite dist/.
Two kinds of update App content (everything inside the window) is the live website, so every web deploy reaches desktop users with the existing refresh prompt. The shell (window, menus, sign-in handoff, updater) changes rarely and updates itself with electron-updater: it downloads in the background and installs on restart. Users never return to the website to get a newer version.
Platform order Mac first (this plan). Windows/Linux only after Mac is proven — not in these PRs.
Distribution Signed + notarized universal .dmg (Apple silicon and Intel in one file), published to GitHub Releases on natyconnor/berean-desktop, with a direct download link on the website login footer. No Mac App Store.
Desktop release cadence Desktop releases are separate from web releases. The web app releases several times a week through release-please; a desktop release happens only when electron/ changes, by bumping electron/package.json and running the desktop-release workflow by hand.
Desktop auth Sign-in opens in the user's default browser and returns to the app through berean://auth. The shell never shows a Google page itself. This uses Convex Auth's existing redirectTo support, so convex/auth.ts does not change. All windows share the persist:berean session partition, so File → New Window is already signed in and the session survives relaunch.
Offline No offline app data / Bible. Shell shows a local offline error page if the production URL cannot load. Network required for UI.
Deep links Custom scheme berean:// only, mirroring web paths (berean://passage/John-1). Normal https://berean.nathanconnor.dev/… links open in the browser as they do today — no Universal Links, no AASA. Signed-out deep links keep the path, show login, then continue to that route after auth.
iPad v1 PWA + “Add to Home Screen” guidance. Mouse/keyboard OK. No touch/pen redesign. Capacitor / App Store deferred (no capacitor/ code in this plan).
UI parity Desktop ≈ web. Hide PWA install UI in Electron. Native title bar. Window title “Berean”. Min size 1024×700; default ~1280×800.
Versioning Two version numbers. The web app keeps the root package.json semver managed by release-please. The shell has its own semver in electron/package.json, starting at 1.0.0; this is the number electron-updater compares.
Accounts Google today. PRs 8–9 propose an email sign-in code and Sign in with Apple. One Convex account everywhere (web + desktop + future iPad); Convex Auth links providers that report the same verified email to the same account.
Tooling Plain Electron + electron-builder + electron-updater (not electron-vite). electron/ is its own small package so the shell does not ship the web app's dependencies. Reuse the existing Vite web app unchanged as the content source.
Marketing / about page Deferred. This plan only adds a Mac download link on the login footer.

Browser sign-in handoff

// 1. Renderer (login page, desktop only):
//      signIn("google", { redirectTo: DESKTOP_AUTH_REDIRECT_PATH })
//    Convex Auth stores a verifier in the app's localStorage, then sets
//    window.location to {CONVEX_SITE_URL}/api/auth/signin/google?...
// 2. Electron main sees will-navigate to a non-app origin:
//      event.preventDefault(); shell.openExternal(url)
//    The app window stays on the login page.
// 3. The user signs in with Google in their own browser. Convex redirects to
//      {SITE_URL}/desktop-auth.html?code=XYZ
// 4. public/desktop-auth.html (static, does NOT load the SPA) navigates to
//      berean://auth?code=XYZ   and shows an "Open Berean" button.
// 5. macOS delivers open-url to Electron main → parseBereanOpenUrl → auth.
//    Main reloads the window that started sign-in at
//      withAuthCode(currentAppUrl, code)   and focuses it.
// 6. ConvexAuthProvider sees ?code= on load, exchanges it with the stored
//    verifier, and strips the param. The user is signed in.
//
// The code is useless without the verifier, which never leaves the app's
// own storage. desktop-auth.html must stay outside the SPA: if the SPA
// loaded there, its ConvexAuthProvider would try to consume the code in
// the browser, where no verifier exists.

Data flow

User downloads Berean.dmg once, drags the app to Applications and launches it → Electron creates a persist:berean window → loads https://berean.nathanconnor.dev (or a berean:// deep-link path) → the existing Vite React SPA runs as it does in Chrome. Clicking Sign in opens the default browser; after Google sign-in the browser hands a one-time code back through berean://auth and the app finishes signing in. Web deploys change Vercel assets; desktop users get the existing /version.json refresh prompt. When the shell itself has a new release, the updater downloads it in the background and offers a restart. If signed out on a deep link, RootRouteComponent shows LoginPage while the router URL stays on the deep link; after auth, AppShell + Outlet render that route. iPad users install via PWA (Add to Home Screen); no separate binary in this plan.

Rules for the agent

Conventions every PR must follow

Workflow

  • One PR at a time, in order. Read files before editing.
  • After code changes run pnpm run agent:check (format → lint → typecheck).
  • Run pnpm test for any PR that adds/edits a *.test.ts.
  • Regenerate Convex types with pnpm run codegen only if Convex files change (only PRs 8–9 touch Convex).
  • Never commit or push unless the orchestrator checkpoint step asks.
  • Do not implement Windows/Linux targets, Capacitor, offline sync, Universal Links, or a marketing homepage unless a PR explicitly lists it.
  • Prefer exact versions (pnpm / save-exact=true) when adding dependencies.
  • Library and tool behaviour in this plan was checked against the versions installed on 2026-11-15. Confirm electron-builder and electron-updater option names against their current docs before relying on them.

Desktop / web rules

  • Electron: contextIsolation: true, nodeIntegration: false, no remote module.
  • Never load arbitrary URLs in a window — only the app origin (berean.nathanconnor.dev or the BEREAN_DESKTOP_URL override) and local offline.html. Everything else goes to the system browser.
  • Do not register Electron menu accelerators that collide with Cmd/Ctrl+K, G, ,, J, or Enter.
  • electron/ is its own package with its own package.json, version and dependencies. Web dependencies must not end up inside the packaged app.
  • Keep the React app a SPA: no Next.js, no SSR requirement.
  • No any; type the preload bridge and pure helpers.
  • If a public Convex function is touched (should be rare): args + returns, auth, indexes, no Date.now() in queries, await every promise.

Depends on: PR 1, PR 2. Unblocks: PR 4, PR 6, and desktop support for any later OAuth provider (PR 9).

Goal

Make Google sign-in work on desktop by doing it in the user's default browser and returning to the app through berean://auth, exactly as described in “Browser sign-in handoff”. Zero Convex changes. This is the riskiest PR in the plan; prove it end to end before building on it.

  • No diff under convex/; web sign-in in a normal browser behaves exactly as before.

Eyes open

Risks & how the plan answers them

Risk Mitigation (baked into the PR sequence)
Google refuses sign-in inside an embedded window The shell never shows Google. PR 2 sends every off-origin navigation to the system browser; PR 3 brings the result back through berean://auth.
The browser handoff has not been run end to end yet It was designed by reading the installed Convex Auth code, not by running it. PR 3 comes early and its acceptance test is the full loop in a packed app, before any signing work.
Another app claims berean:// The code in the link is useless without the verifier, which stays in the app's own storage.
Browser shows an “Open Berean?” prompt Expected for custom schemes. desktop-auth.html explains what to do and offers a button if the automatic hand-back is blocked.
Web releases break the desktop update feed Desktop releases live in their own repo with their own version numbers; release-please never touches them.
Unsigned builds cannot self-update PR 6 publishes only signed builds; the unsigned path exists to prove the pipeline. Manual steps 1–4 gate the first real release.
Agents cannot smoke-test Mac UI Acceptance criteria split mechanical vs behavioral; you run Manual step 5.
Menu accelerators steal app shortcuts Architecture + PR 2 forbid Cmd+K/G/,/J/Enter menu bindings.
Same person ends up with two accounts Providers reporting the same verified email are linked by Convex Auth. The known exception is Apple's Hide My Email (PR 9), which is documented rather than worked around.
