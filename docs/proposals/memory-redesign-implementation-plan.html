Decisions locked before implementation

Fixed constraints resolved with the product owner. Treat as non-negotiable. Rows tagged (changed) intentionally differ from the epic text.

Decision Resolution
One verb, automatic mode Memorize is the only start action, for a verse, a range, a chapter, or a pack. The resolver picks the method; the user never chooses one. Rules (final form, PR 18): one contiguous span in one book with ≥ 4 verses and ≤ 20 chapters becomes a passage, unless all of it groups into a single learning piece (≤ MAX_GROUP_WORDS = 60 words), in which case it is one verse card. 1–3 verses become one verse card. Several separate spans become a pack. More than 20 chapters is rejected. Until PR 18 ships: whole chapters become passages and partial ranges of more than 3 verses become packs.
Passage threshold is 4+ verses Owner asked whether 5+ is better. 4+ was chosen because many well-known passages are exactly 4 verses (1 Corinthians 13:4–7, Isaiah 40:28–31, Philippians 4:4–7); at 5+ they would become four unrelated cards with no recite-through. The single-piece guard keeps very short 4-verse ranges as one card.
A heart means "I love this" Hearting never starts memorizing. Every memorize path also hearts the target when no existing heart covers it. Unhearting something being memorized asks first: "Unhearting also stops memorizing it." with Keep / Unheart and stop. The server enforces invariant I1 (see Architecture) regardless of UI.
One heart per passage Starting a passage writes one savedVerses span row per chapter, linked by passageMemoryId. It writes no per-verse hearts and never unhearts anything. Verses the user hearted individually keep their own hearts. The reader shows the passage heart in the left gutter with a progress ring and a rail over the passage's verses.
(changed) Absorb on passage start Standalone verse items (in Memory, not in any custom pack) that lie fully inside a newly started passage stop being separate items (inMemory: false) after their progress seeds the passage pieces. Nothing is due twice. Hearts are untouched; review history is kept.
(changed) Pack pacing Pack members enter Memory as Up next (status new, inMemory: true). Each pack keeps up to PACK_ACTIVE_LEARNING_CAP = 3 verses learning at once; the next Up-next verses join Today automatically as earlier ones finish learning. A per-row Learn starts one early. A verse memorized on its own starts learning immediately. Pack learn estimate = 3 × ceil(n / 3) days. Reason: without pacing, memorizing "100 Verses Every Christian Should Know" would make every verse due today.
Hearted-only verses leave Memory Migration rule: inMemory = isHearted && (status ≠ "new" || in a custom pack || inside a scope pack's scope || inside an active passage). Everything else stays hearted and appears in "From your hearts" on Today and in Go to passage → Hearted. Nothing is deleted.
(changed) Migration runs lazily per user Besides an internal global migration, the app calls verseMemory.ensureInMemoryBackfill once per session for the signed-in user (flagged by userMemoryStats.inMemoryBackfilledAt). Deploying the branch never leaves Memory empty while someone forgets to run a migration.
Today is the one home /memory is Today. No tabs. Exactly one primary button. Stats live behind "Your progress"; the full list lives behind "Your verses".
(changed) Drawers plus full pages, both functional Your progress, Your verses, pack/passage detail, and verse detail open as drawers over Today (right side ≥ 640px, a 92vh bottom sheet below), addressed by /memory?panel=…. Each has a full page that renders the same body component, for deep links and for arriving from other contexts such as the reader. Drawers are not view-only: rename, reorder, add, remove and stop all work in both. The drawer header has Open full page. There is no stacking: going from Your verses into a pack swaps the content and shows "‹ Your verses" (from=verses). Open, swap and close push history, so Back steps through them. The owner wants to iterate on this; keep the drawer/page split in one host component so it is cheap to change.
(changed) Session return Every session route takes a validated return search param (an internal path including its search string). Done and the session's back link go there: exactly where the session started, including an open drawer. If it is missing or invalid, use history back, else /memory. No row-highlight or toast on return (the session summary already showed the result).
(changed) Heart nudge After every heart of a verse or range that is not being memorized, show the anchored popover ("Saved to your hearts" / "Memorize {ref}?" / Memorize · Not now, plus a small Don't ask again link), until the user picks Don't ask again (feature hint heart-memorize-nudge dismissed). Auto-dismiss after 6 s, no focus steal, Esc and click-away close it.
Reader chrome No per-verse Memorize button. The ring around a heart is the memory indicator. The selection bar (range · Heart · Memorize · ×) appears only for selections of 2+ verses and replaces the grouped-range heart column. The chapter header gets a Memorize button beside the chapter-note well.
(changed) Practice copy is honest A practice attempt can count once as an early review (earlyReviewApplied in src/lib/memory-scheduler.ts). Never claim "doesn't change your schedule". Extra practice tooltip: "Go over anything you've memorized, any time." Scheduler behavior is unchanged.
Stop memorizing Verse: inMemory: false; history and heart kept; memorizing again resumes the schedule. Passage: progress is deleted (existing passageMemory delete behavior), the pack is removed, the heart stays as a plain range heart (passageMemoryId cleared). Confirm copy: "This clears your progress on {title}." Pack: the pack is deleted; members not in another pack stop memorizing (progress kept if restarted); hearts kept.
Words "Pack" stays (never "Collection"). Status chips: New · Learning · Memorized · Mastered (never "Reviewing"). "Your verses", "Your progress", "Suggestions" (never "Presets"). Never show scope, custom, preset, unit, piece, rope, frontier, band, ease, Guided, Challenge.
Honest time Learning time ("Learn it in about N days") and mastery time ("Mastered in about 2 months") are always separate facts and never one number.
Keyboard No new shortcuts. Esc closes drawers, sheets, dialogs and popovers (Radix default). Reorder has a keyboard path (Move up / Move down).
Deferred / dropped The share-card image (the passage moment ships with Done only). Word search in New pack (no ESV search API exists; reference search plus From your hearts). The launch announcement (already removed in #274). Reminders, chart redesign, scheduler constants. Swipe-to-close on bottom sheets (× / Esc / scrim instead; no new gesture dependency).

Invariants (server-enforced from PR 3)

  • I1: inMemory === true ⇒ the verse's span is covered by at least one heart: an exact savedVerses row, a containing span row, or a passage heart. Memorize adds a heart when none covers the span. Unhearting stops memorizing every in-memory item that loses coverage. If the removed heart has passageMemoryId, it stops that passage.
  • I2: Queues, counts, badges, stats, library, and pack membership read inMemory only. isHearted is display-only.
  • I3: Passage members are not separate verse items (absorb on start, see Decisions).
  • I4: Custom pack membership = packVerses rows whose verse is inMemory. Legacy scope packs (not in passage mode) = scope ∩ inMemory. packVerses rows survive stop/unheart so memorizing again restores membership.
  • I5: Status new means "Up next in a pack". A verse memorized on its own starts at learning, step 0, dueAt = now.

Data flow

A reader taps Memorize Psalm 16 in the chapter header (or selects verses and taps Memorize in the selection bar, or taps Memorize in the heart popover, Today search, From your hearts, a suggestion, or New pack). Every entry point calls useMemorizeSheet().open(target). The sheet runs resolveMemorizeTarget (pure) to get the mode, title and counts, reads verseMemory.memorizeStatus to detect "already memorizing" / "part of" and whether a heart line is needed, and shows the plan from memorize-plan.ts.
