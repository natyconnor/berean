Scope-pack auto-heart, cohort learning, and unified recitation

Opt in to heart a scoped pack as intelligent memory units, learn those units together in one in-order rail, then — once they have graduated — review the whole scope as a single recitation whose schedule stays in lockstep.

Settled decisions

Decisions locked before implementation

Fixed constraints resolved with the product owner. Treat as non-negotiable. Remaining product nits in this table are defaults chosen so implementers do not stall.

Decision Resolution
Learn vs review card shape Learning a scoped pack is many small cards, one per hearted span, default in-order in the existing rail. After every member has graduated, the user may review the whole scope as one concatenated recitation card.
Existing hearts Auto-heart and Heart remaining never unheart, merge, split, or retarget an existing span. Occupied verses are holes: new groups form only in the uncovered gaps.
Chapter cap Auto-heart / Heart remaining is allowed only when the scope enumerates at most AUTO_HEART_MAX_CHAPTERS = 20 chapters. Larger scopes (including empty-books “All Scripture”) disable the control and show a tooltip explaining the 20-chapter ESV limit. Small books (Jude, Obadiah, Philemon, …) are fine.
Daily learning ration No new cap on how many spans may be enrolled in one day. “Learn this pack” queues every new / due-for- learning member into one session. Per-span Guided/Challenge soft-lock until tomorrow still applies. The user may stop mid-rail and continue tomorrow.
Unified recitation scheduling Enabling “Review as one passage” pulls every review-phase member due to now, copies a conservative canonical schedule onto all of them, and from then on one recitation grade is written to every member so they stay on the same dueAt. The pack stores unifiedReviewEnabled. Global due-queue and memoryStats.due hide those members and count the pack as one due item.
Preview Show a compact, chapter-grouped chip list of proposed units (refs + kept existing hearts), not a wall of verse text. Default auto-heart checkbox is off.
Grouping caps Hard breaks: occupied verse, chapter boundary, editorial heading, subheading, paragraph break (\n\n). Soft merge when the current group does not end a sentence, or both sides are short (≤ SHORT_VERSE_WORDS = 10), provided the group stays ≤ 4 verses and ≤ 40 words.
Unified lapse One card, one grade. A lapse on the recitation lapses every member together (same scheduleNext output copied to all). Harsh but consistent with lockstep.
Custom packs / Study Auto-heart, Heart remaining, and unified recitation are scope-pack only. Study “Memorize this scope” is unchanged in this plan; the user can heart remaining from the pack that landing creates.
Turning unified off A pack switch can disable unified recitation. Due dates stay wherever the last unified grade left them (already in sync). Members reappear individually in the global due queue. No attempt to restore pre-unify intervals.

Walk uncovered verses in order. Start or flush a group on: occupied hole, chapter boundary (caller splits chapters), heading or subheading on the next verse, paragraph break (previous verse text contains or ends with \n\n), or caps (4 verses / 40 words). Otherwise merge if the current group does not verseEndsSentence, or if both the current group and the next verse are ≤ 10 words. Poetry without periods still stops on paragraph, heading, and caps.

Data flow

User builds a scope pack (≤ 20 chapters) and may check “Heart verses in this scope.” The client enumerates chapters, fetches ESV via getChaptersBatch per book, runs groupChapterForHearting against current hearts, and shows chips. On create it writes the pack, then chunks proposed (not kept) spans through heartMany. On the pack, Heart remaining repeats that gap-fill. Learn this pack calls enrollLearning then /memory/$packId/learn — many in-order cards, same daily band lock. When every member is review-phase, the user enables unified recitation: schedules sync to now, Review becomes one concatenated card, and a single grade keeps every member due together.

Convex & TypeScript

  • Every public query/mutation has args and returns validators.
  • Auth via getCurrentUserId / getCurrentUserIdOrNull; verify pack ownership with loadOwnedPack.
  • Never call Date.now() inside a query — pass now in.

  • Do not touch existing hearts. Overlap → skip, never delete or patch savedVerses rows you did not create.
  • Reuse adjustUserMemoryStats on every status change. Do not reimplement stats math.

Implementation steps

  • Eligibility: scope pack, ≥1 member, every member isReviewPhase. If some are still learning, do not show the switch (or show it disabled with “Finish learning this pack first”).
  • Switch off → on: dialog explaining that every unit becomes due today and future reviews are one recitation on one schedule. Confirm → setUnifiedReview({ enabled: true, now }) → optionally navigate straight into pack review.
  • Switch on → off: setUnifiedReview({ enabled: false }) with lighter copy (they remain in sync until individual reviews happen).
  • Pack Review when enabled: one composite card even if some members were not due before enable (enable already pulled them). Word count is concatenated text for the long-verse rep curve on any future learning lapse.
  • Long passage UX: the existing hidden-from-memory textarea must remain usable — min-height grows, scroll inside the card, verse numbers may be omitted in the prompt (it’s one recitation) but the title is the pack name plus a quiet “n verses” subtitle. Do not require typing verse numbers.
  • After a successful grade, session-complete is a single summary (one accuracy). All members now share the next dueAt; pack dueCount is 0 until that day.
  • Opus focus: the enable moment (awkward 2-due-then-2-not problem) should feel like the solution, not a settings footnote. Prefer a short explanation + one confirm over a dense settings panel.

Acceptance criteria

  • pnpm run agent:check passes.
  • Pack review with the flag off is still N due span cards.
  • Composite record path does not call verseMemory.recordAttempt.
  • Behavioral / visual (manual): enable unified on a graduated chapter pack → one card with full text; a grade updates every member’s dueAt identically; global Review no longer lists those spans individually; disable returns them to the global queue still sharing that dueAt.
